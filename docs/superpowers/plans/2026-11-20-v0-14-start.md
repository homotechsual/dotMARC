# Start of 0.14.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Start 0.14.0 on `develop`, point the in-app link at the new Alert rules docs page, and stop a group-limited API key removing a domain from the last of its own groups.

**Architecture:** Three independent, small changes, one commit each. None touches the bulk DNS push work.

**Tech Stack:** .NET 10, EF Core + Npgsql, ASP.NET minimal APIs, xUnit with the Postgres container fixture, Node scripts.

**Spec:** [roadmap items 0, 4 and 8](2026-11-20-v0-14-0-roadmap.md) and the group-limited rule in [add to group](../specs/2026-11-20-add-domain-to-group-from-overview-design.md).

## Global Constraints

* No em dashes in any prose, comment, docs or commit message. Meaningful variable names, including in tests. Warnings fail the build. No hard line wraps in markdown.
* Branch `develop`, one commit per task, no push without the user's go-ahead.
* `website/data/openapi/dotmarc-api.json` is regenerated with `node scripts/update-openapi.mjs` whenever the API's version or models change, and `OpenApiDocumentTests.TheCommittedCopy_MatchesTheApp` enforces it.

## Review Focus

* A scoped key can still move a domain between its own groups, and can still set groups when the domain also sits in groups the key cannot see (those are kept, as the API documents).
* An unscoped key and the web UI behave exactly as before, including removing every group.
* The refused request changes nothing: the domain's groups are as they were.

### Task 3: A group-limited key cannot remove the last of its own groups

**Files:**
- Modify: `src/DotMarc/Api/DomainWriteEndpoints.cs` (`SetGroupsAsync`), `website/docs/api.mdx` (Keys limited to groups)
- Test: `test/DotMarc.Tests/Api/DomainWriteEndpointTests.cs` (add to the existing scoped-key tests; find the existing set-groups tests first and follow their host setup)

**Interfaces:**
- Consumes: `ApiScope.IsScoped`, `ApiScope.Includes(groupId)`, `ApiProblems.Validation(field, message)`.
- Produces: a refusal with field `groupIds` and the message "This would take the domain out of every group this key can see." when the resulting groups (the requested ones plus the ones kept because the key cannot see them) include none the key can see.

- [ ] **Step 1: Write failing tests** with a scoped key (`CreateKeyAsync([Permission.DomainsEdit], scopedGroupIds: [groupA])`):
  * a domain only in group A, request `groupIds: []` is refused with a 4xx naming `groupIds`, and the domain is still in group A.
  * a domain in groups A and hidden group H, request `[]` is refused, and the domain is still in both.
  * a domain in group A, request `[groupB]` where B is also the key's own group is accepted, and the domain ends in B only.
  * a domain in A and H, request `[A]` is accepted and H is kept.
  * an unscoped key with `[]` is accepted and the domain ends with no groups.
- [ ] **Step 2: Run** `dotnet test test/DotMarc.Tests --filter DomainWriteEndpointTests`. Expected: the two refusal tests FAIL.
- [ ] **Step 3: Implement** the check in `SetGroupsAsync` after `keptOutsideScope` is worked out: when `scope.IsScoped` and no id in the final list satisfies `scope.Includes`, return the validation problem before calling `SetDomainGroupsAsync`.
- [ ] **Step 4: Docs.** Under "Keys limited to groups" in `api.mdx`, add one sentence: such a key can't remove a domain from the last of its own groups, because it would no longer see the domain.
- [ ] **Step 5: Run the DomainWriteEndpoint and OpenApi tests.** Expected: PASS. If the OpenAPI copy no longer matches, regenerate it.
- [ ] **Step 6: Commit** `Stop a group-limited key removing a domain from its last group`.

# Import domains

**Domains > Import domains** adds many domains at once, and can update the groups, tags and settings of domains you already monitor. Paste a list, or choose a CSV or Excel (`.xlsx`) file. Nothing is saved until you check the preview and confirm, and the whole import is saved at once or not at all.

The page has a sample CSV and a sample Excel file to start from.

The preview and results use visible domain search, sort and one Filters panel for status or outcome. Unresolved names have their own search. These controls only change which rows you see: confirming an import still applies the complete plan, including rows hidden by search or filters.

## Add just one domain

Use **Add a domain** at the top of the initial Import page to save one domain immediately without preparing an import. It uses the same validation, duplicate handling and permissions as Dashboard and Domains, where **Add domain** reveals the inputs on demand. **Add to group** starts with the group filter from the page you came from; change or clear it as appropriate. Scoped editors must keep a group in their scope, and assigning one requires domain-edit permission. No baseline is required and DNS is not changed.

**Advanced** is collapsed initially. It lets authorised users set a DMARC policy override (`p`/`sp`), monitoring, DKIM selectors and MTA-STS hosting settings before saving. Policy overrides need `BaselinesManage`, monitoring/DKIM need `DomainsEdit`, and MTA-STS needs `MtaStsManage`. All chosen settings and the group assignment are saved together, or none are.

**Open domain and set up DNS** is selected by default: after saving, Overview opens with a DNS-review prompt. Clear it to stay on the page and use the confirmation link instead. [Combined DNS setup](./dns-provider-push.mdx#new-domain-setup) reviews supported records without publishing until you approve and authorize your provider.

This single-domain group choice does not apply to bulk imports: use the **groups** column for those. The single-domain form is hidden while reviewing or viewing the results of a bulk import so that its snapshot stays unchanged.

## Bulk actions on existing domains

On **Domains**, select individual rows or use **Select all**, then **Bulk actions**. When searching or filtering, **Select domains** offers **Select visible** (all matching rows, not just the current viewport) and **Select all** (every accessible domain, including those hidden by filters). Each choice replaces the selection. The toolbar warns when selected domains are hidden; actions include those domains. Selection is shared across group views without processing a domain twice. Changing filters removes hidden individual/visible selections, but an explicit **Select all** retains hidden domains until cleared or replaced; inaccessible or deleted domains are always removed.

Available actions depend on your permissions:

* **Add/remove group membership** and **Add/remove tags** change only the chosen memberships, leaving other assignments intact. Hidden group memberships are preserved; scoped editors cannot remove their last accessible group.
* **Recheck DNS providers** refreshes provider detection without changing DNS.
* **Run DNS/health checks** runs SPF, MX, DMARC, reporting authorization, TLSRPT and configured DKIM checks, in that order. Completion means checks ran, not that every record passed. It does not publish DNS, provision MTA-STS hosting or deliver alerts.
* **Set DMARC target** needs `BaselinesManage`. Choose a target, or explicitly choose **Inherit group or system target** to clear the selected domains' overrides. Targets change expectations and alerts, not DNS.
* **Remove domains** needs `DomainsDelete` and requires typing `REMOVE`. It permanently deletes the selected domains and all their DMARC/TLS report history. DNS records and externally provisioned hosting are not removed: disable MTA-STS hosting and allow its cleanup to complete first. New incoming reports can rediscover deleted domains.

Each domain is processed separately with a fresh permission and scope check. Results distinguish completed, skipped, failed and not-attempted domains. You can stop remaining actions; completed changes are not rolled back, and an in-progress action may have completed. Refresh and review the current state before retrying.

To remove one domain, open its detail page and use **Remove domain**. The confirmation counts its full report history, including reports older than the detail page's reporting window. Removal is also available under **Show management columns** on Domains.

## Columns

Only the domain is required, so a list of domains, one per line, is a complete import.

| Column | What it holds |
| --- | --- |
| domain | The domain, for example `contoso.example`. |
| groups | Groups, separated by `;`. |
| tags | Tags, separated by `;`. |
| halo client | The HaloPSA client's name. Used only when HaloPSA is connected. |
| monitored | `yes` or `no`. |
| dkim selectors | DKIM selectors, separated by `;`. They replace the domain's list. |
| mta-sts mode | `off`, `none`, `testing` or `enforce`. |
| mta-sts mx hosts | MX hosts, separated by `;`. |
| mta-sts max age | Seconds, from 1 to 31,557,600. |
| connectwise company | The ConnectWise company's name. Used only when ConnectWise is connected. |
| autotask company | The Autotask company's name. Used only when Autotask is connected. |
| ninjaone organisation | The NinjaOne organisation's name. Used only when NinjaOne is connected. |
| superops client | The SuperOps client's name. Used only when SuperOps is connected. |

Cells copied from a spreadsheet and pasted straight in work too: they arrive separated by tabs rather than commas.

Without a header row, columns are read in that order. With a header row (one of its cells is `domain`), columns can be in any order and any can be left out.

A blank cell leaves that value as it is. A value that doesn't make sense, such as `monitored` set to `maybe`, is left out and the preview says why; the rest of the row still imports.

Turning MTA-STS on needs MX hosts. If a row doesn't give them and the domain has none saved, dotMARC looks them up in DNS, as the Enable button on a domain's page does.

## Domains you already monitor

Choose what happens to them on the preview:

* **Skip them** (the default) leaves them untouched.
* **Add** adds the listed groups and tags, and applies any settings given. Write `-Name` to remove a group or tag, for example `Client A;-Old Client`.
* **Match the file** makes each domain's groups and tags exactly what its row lists, and applies any settings given. A blank groups or tags cell removes them all. A column that isn't in the file is left alone.

Everything that will be removed is shown in red on the preview.

## Names that don't exist yet

If a group, tag or PSA company in the import doesn't exist, the preview lists it. For each one, choose to create it, map it to an existing one, or leave it out. A name that's the same as an existing one apart from punctuation or an ending like "Ltd" is mapped to it for you; close spellings are suggested, to catch typos, but you choose them. PSA companies can't be created from dotMARC: each company column is matched against that PSA's own list. A name that only differs in capital letters is treated as the existing one.

## Permissions

Importing needs the `DomainsAdd` permission. Groups, tags, PSA companies, monitoring and DKIM selectors also need `DomainsEdit`, and the MTA-STS columns need `MtaStsManage`. Creating groups or tags needs `GroupsAdd` or `TagsAdd`. Without a permission, that column is ignored and the preview says so. See [Permissions and access](./permissions-and-access.mdx).

## Limits

An import can have up to 1,000 rows. CSV files and pasted text can be up to 1 MB, and Excel files up to 5 MB. Old `.xls` files can't be read: save them as `.xlsx` or CSV.

## After importing

Every change is recorded in the [audit log](./audit-log.mdx), as if you'd made it by hand, with one extra entry summarising the import. New domains get their DNS health checks within the next polling cycle.

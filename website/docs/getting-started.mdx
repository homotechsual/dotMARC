# Getting Started

dotMARC needs **two separate** Microsoft Entra app registrations, one to read the DMARC reports
mailbox and one to sign people in to the dashboard. Do not reuse one for both purposes. Each
deployment guide below walks you through creating them at the point you need them, so pick how you
want to run dotMARC first.

## Configure

:::warning[This is a reference, not a setup guide]

This table only explains what each setting means. It is not the place to set dotMARC up, and following it
on its own will leave you with a half-configured install. All setup instructions, including creating the
Entra app registrations and supplying these values, are in the deployment guides:
[Deploy with Docker](./deploy-with-docker.mdx) or [Deploy to Azure](./deploy-to-azure.mdx).

:::

Everything dotMARC reads is set through configuration. Both deployment guides set these for you.

## Choose how to run it

Both paths run the exact same product image and cover the same ground end to end - pick whichever
fits how you already operate:

| | [Deploy with Docker](./deploy-with-docker.mdx) | [Deploy to Azure](./deploy-to-azure.mdx) |
| --- | --- | --- |
| Best for | Self-hosters: your own hardware, a home/office server, or any VPS | Teams already running infrastructure on Azure |
| You manage | The host, Docker, TLS (a bundled Caddy setup handles this for you) | Nothing beyond the app config - Container Apps handles the rest |
| Database | PostgreSQL container, your own volume/backups | Managed Azure Database for PostgreSQL Flexible Server |
| Cost model | Whatever your own hardware/VPS costs | Pay-as-you-go Azure resources |

Not sure? [**Deploy with Docker**](./deploy-with-docker.mdx) is the faster path to a first working instance - a single
`docker compose` command gets you a complete stack, including HTTPS. [**Deploy to Azure**](./deploy-to-azure.mdx) trades a
bit more setup for infrastructure you don't have to maintain yourself.

## What you'll see

Once your first DMARC report arrives (this looks the same regardless of which path you chose
above), the dashboard shows pass/fail rates, DNS status, and polling status across every monitored
domain:
